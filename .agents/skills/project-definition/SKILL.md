# Purpose

사업 또는 시스템 개발 요청을
명확한 프로젝트 정의로 구조화한다.

# Applicable Stages

DEFINE

# Primary Agent

@pm

# Inputs

- project.yaml
- 사업 또는 시스템 아이디어
- 해결하려는 문제
- 사용자/고객 정보
- 알려진 제약사항
- 관련 사업자료

# Procedure

1. 해결하려는 문제를 사실 중심으로 정리한다.
2. 문제와 Project Goal을 연결한다.
3. Target User와 Stakeholder를 구분한다.
4. In Scope를 정의한다.
5. Out of Scope를 명시한다.
6. Success Metric 후보를 작성한다.
7. 일정, 비용, 규제, 보안, 기술 제약을 식별한다.
8. 확정사항과 Assumption을 분리한다.
9. 초기 Risk를 작성한다.
10. 사람이 결정해야 할 내용을 Open Question으로 분리한다.

# Checklist

- [ ] Problem이 명확하다.
- [ ] Goal이 Problem과 연결된다.
- [ ] Target User가 존재한다.
- [ ] In Scope가 있다.
- [ ] Out of Scope가 있다.
- [ ] Success Metric이 있다.
- [ ] Assumption이 별도로 관리된다.
- [ ] Risk가 기록된다.
- [ ] Open Question이 분리된다.

# Blockers

다음이면 STOP한다.

- 해결하려는 문제를 알 수 없음
- 프로젝트 목적이 서로 충돌
- Scope를 결정할 핵심정보 부족
- 사업적 우선순위 결정 필요

# Output

- Project Definition 분석결과
- Scope 후보
- Risk
- Open Question

# Traceability

Business Problem
→ Project Goal
→ Scope
→ Success Metric
